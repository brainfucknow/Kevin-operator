Act as the Kevin orchestrator. Read `kevin/roles/orchestrator.md`
and follow it for the request below.

Forms:
- `/kevin:swarm <feature request>`: create a task and start the pipeline.
- `/kevin:swarm status`: print `kevin ls` and explain each row.
- `/kevin:swarm resume <id>`: continue a task from its current stage.
- `/kevin:swarm approve <id>`, `/kevin:swarm reject <id> <reason>`, `/kevin:swarm answer <id> <text>`: operator decisions.

Request: $ARGUMENTS

## Plugin subagents

Vibe names this plugin's subagents `kevin:<role>`, for example `kevin:coder`.
Delegate to those names, one per subagent role in `kevin/roles.conf`.

## Session policy for Vibe

This skill adds one operator rule to the orchestrator prompt.

Do not merge a finished task into `main` on your own. For each task that
reaches `done`:

1. Push the task branch: `git push origin swarm/<id>`.
2. Open a pull request from that branch into `main`. Put `Fixes #<N>` in
   the body when the task fixes GitHub issue #N.
3. Run the `pr-reviewer` review of that pull request, per the Pull Request
   Review section of `kevin/roles/orchestrator.md`.
4. A pull request merges only after a human has reviewed and approved it on
   GitHub (branch protection on `main` requires one approving review) and
   the `pr-reviewer` review is done, and only when the operator accepts its
   findings. Never run `kevin finish <id>` into `main` unless the operator
   explicitly asks for it.

Commits made directly in the operator session (not kevin bookkeeping commits) end with the "Generated by Mistral Vibe." and "Co-Authored-By: Mistral Vibe <vibe@mistral.ai>" trailer lines.
